This content assumes you have Babylon command line access . FAQ How to find the right anarchy-runner, given a GUID? Anarchy Pods Anarchy is deployed in several namespaces. These namespaces all have the label app.kubernetes.io/name=anarchy : $ oc get namespace -l app.kubernetes.io/name=anarchy NAME STATUS AGE anarchy-k8s-config Active 239d anarchy-operator Active 343d babylon-anarchy-cpbu Active 3h57m babylon-anarchy-test Active 3h56m The anarchy-k8s-config namespace currently manages GitOps operations against our clusters. The other namespaces are used for Babylon processing. The anarchy-operator namespace is currently our primary namespace for Babylon usage, but this work should be distributed across several instances soon by configuring __meta__.anarchy.namespace in AgnosticV. Code examples below reference anarchy-operator , but be sure to adjust this to whichever anarchy namespace you are troubleshooting. In each Anarchy namespace there are two main types of pods: $ oc get pod -n anarchy-operator NAME READY STATUS RESTARTS AGE anarchy-7c7497f6c6-7b8fg 1/1 Running 0 120m anarchy-7c7497f6c6-wh6wm 1/1 Running 0 120m anarchy-runner-default-2ktkv 1/1 Running 0 90m anarchy-runner-default-665gj 1/1 Running 0 4h34m anarchy-runner-default-6tkd7 1/1 Running 0 106m anarchy-runner-default-frglk 1/1 Running 0 4h34m anarchy-runner-default-gz7pr 1/1 Running 0 120m anarchy-runner-default-sbg9j 1/1 Running 0 4h34m anarchy-runner-default-tdlbv 1/1 Running 0 4h34m anarchy-runner-default-tzvc4 1/1 Running 0 4h34m The anarchy-* pods make up the core main Anarchy operator and the anarchy-runner-* pods are responsible for processing Ansible execution.
