Troubleshooting procedure of Replik8s Snapshot Age Issue. Issue: Description: This monitor checks that the replik8s last snapshot age on the 2 production primary babylon servers less than 2 and 4 hours old. This monitor will provide the following information to the script, and compares the UTC date times between now and when the last backup was taken (requires parsing a YAML string out of the OCP ConfigMap "babylon". See the below code for details $ oc get configmap -n babylon-cross-cluster-backup babylon -o jsonpath={.data.status} | yq eval .recoveryPoints[-1] - 2023-01-08T09:35:39.273804Z Once this is determined, it uses a configurable option --critical or --warning (in seconds) to provide enough information to check if the critical and warning values are exceeded. We use 4 hours and 2 hours (14400s and 7200s, respectively) to provide Icinga detail for the check. Steps to follow: Login to the Babylon cluster in question Instructions from JK Access the replik8s namespace. Scale down replik8s to 0 Delete the associated pvc and recreate it Scale back up to the original number of pods If not obvious, contact AnarchyDevs for assistance 1) Login to Babyon cluster in question and access the replikas8s namespace CLI output : 2) Scale down replik8s to 0 Under Home → Project search for Babylon-cross-cluster-backup, Under workloads→ deployments → Action → edit Pod Count > make it 0 3) Delete the associated pvc and recreate it Delete the PVC with name replik8s, it will take a while then recreate PVC with will below options and annotations Select any of the node from the cluster. Once the PVC is created just make sure it is created in AWS GPTE-infra account. 4) Scale back up to the original number of pods Again go back to the project and make the pod count to 1. Make sure the cron Job ran successfully and alert is cleared.
