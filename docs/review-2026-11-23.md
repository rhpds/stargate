## 3. Findings

### P0 — fix before the next demo/release

**P0.1 Shell injection in the remediation console** `[verified]`
`api/routers/dashboard/remediation.py:766-791, 871-879` and `:1265-1272`.
`_is_safe_command` splits on `|` and validates only the first segment's verb;
it never rejects `;`, `&&`, `$(...)`, backticks, `>` or newlines. Execution is
`subprocess.run(cmd, shell=True)` whenever the string contains a pipe. Any
caller who can reach the endpoint can run arbitrary commands with the
executor kubeconfig: `oc get pods | grep x; curl …`. The README claim that
"all `oc` parameters are validated" does not hold here.
**Fix:** argv arrays only, `shlex.split`, allowlist per token, no shell; or run
pipes in-process. Add a table test with metacharacters.

**P0.2 MCP caller identity is a process-global** `[verified]`
`api/app.py:109` writes `os.environ["_MCP_CALLER_KEY"]`; `api/mcp_server.py:357`
reads it. Concurrent MCP requests overwrite each other, so a read-only key can
inherit an admin key's scope for `review_diagnosis` / `comment_action`, and
audit attribution is wrong. `[static: the audit line attributes to the caller]`
**Fix:** pass the key through request state/contextvar into the tool call; never
mutate `os.environ`.

**P0.3 Missing evidence is scored as failure** `[verified]`
`engine/rubric_evaluator.py:56-58, 86-88`:
`passed = None if name in evidence and value is None else _is_truthy(value)`.
An **absent** key becomes `_is_truthy(None) == False`, so a required criterion
that was never collected is a hard FAIL, not INDETERMINATE. `[static]` this is
why taxonomies can emit `deployment_missing` from "no data". Entry failures
short-circuit before the unobserved check.
**Fix:** distinguish `absent` from `observed false`; a required absent key
should block the stage as INDETERMINATE. Measure how often keys are absent
before changing, then add a regression test.

**P0.4 Route probe exists but is switched off in production** `[verified]`
`collectors/openshift/probe_route_health.py` + `cli/stargate.py:308` gate on
`STARGATE_ROUTE_PROBE`, which appears in **no Helm values or template**.
`rubrics/platform/route-ready.yaml` still marks `health_endpoint_returns_200`
`required: false`. So the probe collector added in #154 never runs in prod, and
route-ready still cannot pass. The handoff's #1 item is *implemented but not
enabled*; #159 fixed `warn → ready`, but not this.
**Fix:** set `STARGATE_ROUTE_PROBE=1` + a timeout in `values-infra01.yaml`, make
the criterion required, add "healthy route reaches pass" test. Expect ~265 labs
to move out of `unknown` (re-measure first).

**P0.5 Rotation sync can wipe ticket history** `[verified]`
`collectors/rotation_sync.py:261-267`: when `keys` is empty it deletes **all**
rotation tickets; a partial or failed Jira page deletes everything not in the
page. Any pagination bug becomes data loss.
**Fix:** refuse to prune on an empty/failed fetch; prune only on a complete
snapshot (explicit completeness flag).

**P0.6 Deploy script is destructive to credentials** `[verified]`
`scripts/deploy-infra01.sh:45-55` deletes `stargate-kubeconfigs` and recreates
it with ocpv06–09 + infra/executor — **omitting `kubeconfig-ocpv03`**, which
`values-infra01.yaml:34` asks the scheduler to scan. Every run of the script
silently un-scans ocpv03 until someone re-adds the key.
**Fix:** `oc create secret ... --dry-run=client -o yaml | oc apply -f -`, and
build the key list from the same fleet registry the scheduler uses.
